# Skiller Integration Design

Status: CONVERGED / implementation plan on `skiller-integration-phase-a`
Date: 2026-06-15
Scope: Phase A of skiller Milestone 5 for Talking Stick

## Problem

Talking Stick still owns the skill-directory installer in TypeScript:

- `src/skill-install.ts` resolves shared vs proprietary skill targets, writes symlinks/copies, syncs installed skill copies, and removes duplicate proprietary symlinks.
- `src/harness-model.ts` keeps a local harness skill-loading registry.
- `src/cli/install-commands.ts` adapts those helpers into `tt install`, `tt uninstall`, and startup skill sync.

Skiller now has the shared installer core and subprocess JSON contract. The active task is to make Talking Stick use that binary where available, while keeping a safe fallback until skiller has a published distribution and one stable adopter release.

## Current Evidence

- Skiller M5 explicitly names Talking Stick as the conformance oracle and says to keep the TypeScript path as emergency fallback while replaying install, uninstall, sync, duplicate cleanup, stale MCP cleanup, Grok extras, and shared `.agents` behavior through skiller.
- A locally built skiller binary currently supports `version --json`, `registry --json`, `plan --json`, `install --json`, `uninstall --json`, `cleanup-duplicates --json`, `sync --json`, and `status --json`.
- The registry maps `codex`, `antigravity`, `grok`, and `opencode` as shared readers of `agents`, with proprietary duplicate roots for codex/grok/opencode.
- Skiller has a published `v0.1.0` release with per-platform archives and `checksums.txt`, so Talking Stick can bootstrap the binary automatically during package installation.

## Decisions

### D1 Distribution

Automatically install skiller as part of Talking Stick package installation, then use PATH/detection plus fallback at runtime.

Postinstall behavior:

1. Skip only when `TALKING_STICK_DISABLE_SKILLER_BOOTSTRAP=1` or `TALKING_STICK_DISABLE_SKILLER=1`.
2. Reuse a compatible existing skiller binary if one is already available.
3. Otherwise download skiller `v0.1.0` from GitHub Releases, verify the archive against `checksums.txt`, and install it to `~/.local/bin` by default.
4. If bootstrap fails, warn and keep the TypeScript fallback available. `TALKING_STICK_REQUIRE_SKILLER=1` turns bootstrap failure into a package-install failure.

Runtime resolution order:

1. `SKILLER_BIN`
2. `skiller` on `PATH`
3. `~/.local/bin/skiller`

No download-on-first-command in Phase A; automatic install happens at Talking Stick install/update time. The adapter verifies `skiller version --json` against a pinned minimum before use.

### D2 Default Activation

Auto-detect a compatible skiller binary and use it by default. If no compatible binary exists, use the current TypeScript path. Operators can force the old path with `TALKING_STICK_DISABLE_SKILLER=1`; tests can force the new path by setting `SKILLER_BIN`.

Skiller command failures after a valid binary is selected are not silently replayed through TypeScript. A skiller conflict/block is a safety decision, not an availability failure.

### D3 Grok Hook

Keep Grok hook placement in TypeScript for Phase A.

Reasons:

- The hook content is generated by Talking Stick and coupled to `tt grok-session-hook`.
- Existing skip-missing behavior depends on the local Grok config root.
- Moving it to skiller `[[extras]]` is useful, but it is not required to remove duplicated skill-directory logic.

### D4 State Directory

Use `${TALKING_STICK_DATA_DIR}/skiller` when `TALKING_STICK_DATA_DIR` is set; otherwise use the normal Talking Stick data dir plus `/skiller`. This keeps test isolation and user data locality aligned.

### D5 Release Dependency

Land Phase A on a feature branch. Skiller `v0.1.0` exists, so this branch can include real postinstall bootstrap. Do not merge to `master` until both agents review the installer safety and fallback behavior.

### D6 Conformance Tests

Add a Talking Stick test layer for the adapter using a fake skiller subprocess. The tests verify:

- binary detection/version gating;
- manifest generation for the real bundled skill;
- install/uninstall/cleanup/sync subprocess arguments;
- TypeScript fallback when skiller is unavailable.

When this repo gains CI for cross-repo tests, add a job that checks out skiller, builds it, sets `SKILLER_BIN`, and runs the same adapter path against a real binary.

## Phase A Implementation

1. Add `src/skiller-adapter.ts`.
   - Locate and version-check skiller.
   - Generate a temp `skiller.toml` manifest for selected harness targets.
   - Run skiller subprocess commands with `--json`, `--home`, and `--state-dir`.
   - Convert skiller action results into existing `InstallResult` / cleanup-result shapes.
2. Wire explicit install commands.
   - `tt install`: skiller `install`; TS fallback; Grok hook remains TS.
   - `tt install --print`: skiller dry-run plan when available; TS fallback.
   - `tt uninstall`: skiller `uninstall` plus skiller `cleanup-duplicates`; TS fallback; MCP cleanup remains TS.
3. Wire maintenance paths.
   - Startup skill sync uses skiller `sync` when available, otherwise `syncInstalledSkills`.
   - Stale duplicate skill cleanup uses skiller `cleanup-duplicates` when available, while stale MCP cleanup stays TypeScript.
4. Add automatic bootstrap.
   - Postinstall installs or verifies skiller `v0.1.0`.
   - Bootstrap verifies checksums before extraction and install.
   - Bootstrap failure leaves Talking Stick usable through fallback unless explicitly required.
5. Keep the old TypeScript helper exports for fallback and tests. Do not delete `skill-install.ts` in this phase.

## Phase B Follow-Up

After skiller has release artifacts:

- bundle or acquire skiller through a documented distribution path;
- make release verification include a real skiller binary, not only a fake subprocess;
- consider moving Grok hook placement into skiller `[[extras]]`;
- add a release note that skiller is the default installer backend with TypeScript fallback.

## Phase C Follow-Up

After one stable skiller-backed release:

- delete duplicated target resolution, directory writes, sync, and duplicate cleanup from `src/skill-install.ts`;
- keep only manifest generation, subprocess adaptation, MCP cleanup, Grok hook generation, and emergency fallback code if still required.
