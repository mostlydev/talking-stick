## Stage 1 — Watch store and reset substrate

End state: `tt watch start` and `tt walk` can acquire a workspace lease, atomically reset a workspace store, honor `--resume`/`--archive`/`--force`, and fail cleanly on workspace-key/canonical-path mismatch. No filesystem watcher yet — the binary just opens a session and exits with a status JSON.

### 1.1 Workspace key + paths

**File:** `src/watch/paths.ts`

### 1.4 Lease + reset flow

**File:** `src/watch/lifecycle.ts`

```ts
export interface OpenSessionInput {
  canonicalPath: string;
  roomId: string;
  resume?: boolean;
  archivePath?: string;
  force?: boolean;
}

export interface OpenSessionResult {
  workspaceKey: string;
  sessionId: string;
  storeDir: string;
  resetMode: "fresh" | "resume";
  attached: false;
}

export interface AttachedResult {
  workspaceKey: string;
  attached: true;
  liveHolderId: string;
  liveRoomId: string;
}

export type LeaseResult = OpenSessionResult | AttachedResult;

export async function acquireWorkspaceLease(input: OpenSessionInput): Promise<LeaseResult>;
```

Algorithm (mirror of design §Session reset):

1. Compute `workspace_key`, ensure registry row exists, validate `canonical_path` matches stored row (hard-fail on collision).
2. Read current `watcher_leases` row. If heartbeat is fresh (within `lease_expires_at`):
   - Same room → return `AttachedResult` (caller reattaches as reader, no wipe).
   - Different room → throw `WatcherActiveConflict` with both room ids.
3. If stale or absent: insert/update lease with own `holder_id` (a uuid), `pid`, `host_id`, `heartbeat_at = now`, `lease_expires_at = now + LEASE_TTL_MS`.
4. If `--resume`: open existing store if present (check `watch_session.room_id` matches input `roomId`; mismatch → `ResumeRoomMismatch` unless `--force`); else fall through to fresh.
5. If pending annotations exist: `flushPendingAnnotations()`. If any remain pending and `!force`: throw `PendingAnnotationsBlockReset`.
6. If `--archive <path>`: tarball `watch.sqlite + blobs/ + projection.git` before any deletion.
7. Atomic reset: `fs.renameSync(workspaceDir, workspaceDir + ".deleting-" + ts)`, `fs.mkdirSync(workspaceDir, { recursive: true })`, run session migrations, insert `watch_session` row, asynchronously `fs.rm` the deleting dir.
8. Update `watch_workspaces.current_room_id`, `current_session_id`, `last_reset_at`.

**RISK — `fs.renameSync` cross-device.** Within `${TALKING_STICK_DATA_DIR}/watch/workspaces/<key>/` everything is on the same filesystem; rename is atomic. The `--store <path>` override could point elsewhere; if rename fails with `EXDEV`, fall back to "copy aside under same parent then rm" with a clear log. Document the precondition that `--store` paths must be on a single filesystem.

**DECISION — lease TTL.** 5 minutes (`5 * 60_000`). Watcher heartbeats every 60s. A live process that misses two heartbeats is reclaimable. This matches `ownerLeaseTtlMs: 2_700_000` shape in talking-stick policy but tighter because watcher death without cleanup is more common than coordination owner death.

## Stage 2 — Scanner and classifier

End state: given a workspace and an open session store, the scanner can be invoked synchronously over a path or list of paths, classify each into source/opaque/skipped, write `file_versions` blobs, update `path_heads`, and produce `file_changes` candidates that the next stage will batch.

### 2.3 Single-file scanner

**File:** `src/watch/scanner.ts`

```ts
export interface ScanInput {
  storeDb: BetterSqlite3.Database;
  blobsDir: string;
  workspaceRoot: string;
  config: ClassifyConfig;
}

export interface ScanResult {
  changeKind: "add" | "modify" | "delete" | "noop";
  path: string;
  class: FileClass;
  beforeVersionId: string | null;
  afterVersionId: string | null;
  visible: boolean;             // false for hidden tombstones
  diagnostic?: string;
}

export async function scanOne(path: string, input: ScanInput): Promise<ScanResult>;
```

Implementation follows design §Watcher algorithm `scan_one()` literally, including:
- stat → read → stat for tearing detection (full read for source, streaming sha256 for opaque/truncated)
- UTF-8/UTF-16 BOM carve-out before NUL-byte sniff
- max_track_bytes early-out with tombstone if prior head was projected source
- `path_heads` upsert
- CAS dedup on `version_id = sha256:size`

`writeBlob(versionId, body)` writes to `blobsDir/<sha256[:2]>/<sha256>` if not present. Streaming sha256 uses `crypto.createHash("sha256")` over a `fs.createReadStream` with 64 KiB chunks.

**RISK — torn read retry budget.** Design says up to 3 retries. Implementation retries with 50/100/200ms backoff between attempts. After 3rd torn read, log diagnostic and return `changeKind = "noop"` so the batch journal won't write a fake version.

### 2.4 Tests

**File:** `tests/watch-scanner.test.ts`

- Classify: each default extension and filename produces `'source'`; unknown gets `'opaque'`.
- Binary sniff: ASCII text → text; `0x00` in first 8 KiB without BOM → binary; UTF-16-LE BOM with NULs → text.
- scanOne add: writes blob, inserts `file_versions`, upserts `path_heads`, returns `{ changeKind: "add", class: "source", ... }`.
- scanOne dedup: identical content at second path reuses `version_id`, skips blob write.
- scanOne tearing: monkey-patch read to return between two stats with mismatched mtime → returns noop after retries; no `file_versions` row written.
- scanOne huge file: size > max_track_bytes → updates `path_heads(class='skipped', version_id=NULL)`, no `file_versions`. If prior head was source: also returns hidden tombstone result.
- scanOne source-extension-but-binary: writes `file_versions`, `path_heads.class='opaque'` for that change.
- scanOne over max_blob_bytes: streams sha, no blob, `path_heads.class='source'`, blob_path NULL.
- Path discovery: respects gitignore in git repo; respects custom `.gitignore` in non-git via `ignore` package; always excludes `.git/`, `--store` dir, talking-stick data dir.

## Stage 3 — Batch journal and reconciliation

End state: the watcher process maintains a `dirty_set`, opens/closes batches with adaptive quiet windows, brackets attribution by room event seq, runs periodic reconciliation, and notifies subscribers over local IPC. No diff rendering yet; the journal alone supports a textual `tt watch tail` debug command.

### 3.1 Watcher process

**File:** `src/watch/watcher.ts`

```ts
export interface WatcherOptions {
  paths: WatchPaths;
  workspaceKey: string;
  workspaceRoot: string;
  roomId: string;
  config: WatcherConfig;
  serviceClient: TalkingStickReadClient; // wraps get_room_state, get_room_events, send_message, add_note
}

export class Watcher {
  start(): Promise<void>;
  stop(): Promise<void>;
  onBatch(listener: (batch: BatchSummary) => void): () => void;
}
```

Internals:
- `chokidar.watch(workspaceRoot, { ignoreInitial: true, ignored: [...] })`
- `dirty_set: Set<string>` keyed by absolute path
- `batchTimer` and `tickInterval` (50ms)
- `currentBatch?: { openedAt, closeDeadline, hardDeadline, eventSeqLoSnapshot, attributedToSnapshot }`
- On each event: add to dirty set, bump `closeDeadline = now + quiet_window_ms`, set `hardDeadline = batchOpen + batch_hard_cap_ms`.
- Tick: if a batch is open and `now >= closeDeadline || now >= hardDeadline`, close.
- Reconciliation tick: every `reconcile_interval_ms`, if no batch is open, run `reconcileWorkspace()` which compares `git status -z` + `git ls-files` output against `path_heads` and adds any drift to `dirty_set`. Reconciliation-sourced batches use `change_batches.source = 'reconcile'`.

`TalkingStickReadClient` is a thin wrapper around `mcp__talking-stick__get_room_state` + `get_room_events`. **DECISION — transport.** The watcher is local to the same machine as the MCP server; it shells out via the same SQLite database (`talking-stick.sqlite`) using a read-only better-sqlite3 connection. **RISK — schema coupling.** Importing `TalkingStickService` couples the watcher's stability to coordination-service refactors. Acceptable for v1 (same package, same release cadence). v2 may switch to MCP client if the walker becomes a separate package.

### 3.3 IPC for walker subscribers

**File:** `src/watch/ipc.ts`

Local Unix domain socket at `${workspaceDir}/watcher.sock` (Linux/macOS). On Windows, fall back to a named pipe under `\\.\pipe\talking-stick-watch-<workspaceKey>`. Wire format: newline-delimited JSON, one event per line:

```json
{"type":"batch_closed","batch_id":42,"change_seqs":[101,102,103]}
{"type":"watcher_status","reset_mode":"fresh","baseline_done":true}
```

Walker subscribers connect on startup and read events. If the socket is missing, walker falls back to polling `change_batches` via a 250ms `change_seq > cursor` query.

**DECISION — subscribers count.** Multiple walker panes may connect to the same socket. The watcher fans out write events to all connected sockets; one slow consumer cannot block others (per-socket bounded queue, drop-with-warning if full).

### 3.4 Tests

**File:** `tests/watch-batching.test.ts`

- Single fs event triggers a batch that closes after `quiet_window_ms`.
- Rapid events within window collapse into one batch.
- Hard cap fires when active generator never quiets down; batch closes at `batch_hard_cap_ms`.
- Periodic reconciliation detects path that fs watcher missed (simulate by writing a file with chokidar paused); produces a batch with `source='reconcile'`.
- Attribution: with stable owner across batch window → `kind='owner'`. Owner change mid-batch → `kind='multi_owner'`, `attributed_to=NULL`. Idle room → `kind='none'`.
- IPC: a connected subscriber receives `batch_closed` for each new batch in order.
- Subscriber backpressure: a stuck subscriber gets dropped after queue overflow; other subscribers continue receiving.

## Stage 4 — Projection and diff rendering

End state: a bare git repo at `${workspaceDir}/projection.git` mirrors the source class subset of the workspace, with one commit per closed batch. Walker can request `git diff <prev_tree> <next_tree> -- <path>` and get text diffs back.

### 4.1 Baseline projection commit

**File:** `src/watch/projection.ts`

```ts
export class Projection {
  init(): Promise<void>;            // creates bare repo if absent
  baseline(seedPaths: BaselineEntry[]): Promise<string>;  // returns commit sha
  commitBatch(batch: BatchProjection): Promise<string>;   // returns commit sha
  diff(treeBefore: string, treeAfter: string, path?: string): Promise<string>;
  rebuild(): Promise<void>;
}
```

`init()`:
- `git init --bare --object-format=sha256 ${projectionDir}` (note: requires git ≥ 2.42 for sha256 object format — **DECISION**: pin minimum git version in README, OR fall back to default sha1 with a deprecation note). Lean: sha1 default for v1; sha256 is nice but git compatibility tooling is shakier.
- Configure `core.bare=true`, set commit identity (`watcher@local`), turn off autocrlf.

`baseline(seedPaths)`:
- For every `path_heads.class='source'` row with a stored blob, write the blob into the index via `git update-index --add --cacheinfo`.
- Write tree, commit with message `baseline:<session_id>`, return commit sha. Persist as `watch_session.baseline_git_head`.

`commitBatch(batch)`:
- Start from prior batch tree (or baseline tree).
- For each `file_changes` row in the batch:
  - `class='source'` add/modify with stored blob → `git update-index --add --cacheinfo` for the after-blob.
  - `class='source'` delete → `git update-index --remove`.
  - `class='source'` truncated (no blob) → `git update-index --remove` (prior projected source removed; new state has no renderable body).
  - `class='opaque'` → if path was in projection, `git update-index --remove`; else no-op.
  - `class='skipped'` with `visible=0` (hidden tombstone) → `git update-index --remove`.
- Write tree; if tree differs from prior: commit with `author = attributed_to-converted-to-git-identity, fallback "watcher"`, message `batch:<batch_id>`. Returns commit sha. Empty-tree batches (only opaque/skipped activity) skip the commit and reuse the prior tree.

### 4.2 Diff serving

`diff(treeBefore, treeAfter, path?)` shells `git diff -M --find-renames=85% <treeBefore> <treeAfter> [-- <path>]` and returns stdout. Errors throw `ProjectionDiffError`.

### 4.3 Rebuild

`rebuild()`:
- Detect by running `git rev-parse HEAD` against `projection.git`; if it errors, drop the dir and recreate.
- Replay `change_batches` in order, calling `commitBatch` for each.
- Verifies final tree matches `path_heads`-derived state (via a content-hash crosscheck on `class='source'` rows with blobs); raises if drift.

### 4.4 Tests

**File:** `tests/watch-projection.test.ts`

- Init creates bare repo with sha1 (v1 default).
- Baseline commit: tree contains exactly the source-with-blob path set; opaque, truncated, and skipped paths absent.
- Batch with source add → next commit has new blob; diff shows added lines.
- Batch with source delete → next commit removes path; diff shows deletion.
- Source → opaque transition: projection removes path; diff shows deletion.
- Source → skipped (hidden tombstone): projection removes path; UI never sees a feed item but rebuild stays correct.
- Rename: write same content at `b.ts` after deleting `a.ts`; `git diff -M` reports rename; `file_changes.rename_from` populated by post-process step in scanner that consults `git diff --name-status -M` after batch commit.
- Empty-effective batch (only opaque + skipped activity): no new commit.
- Rebuild: drop projection dir, call `rebuild()`, final tree matches the state it had before drop.

**RISK — rename detection chicken/egg.** scanOne emits `add`/`delete` rows; renames are detected after `commitBatch` by parsing `git diff --name-status -M`. The plan: on batch close, run scanner over all dirty paths to produce candidate file_changes, run `commitBatch`, then run `git diff -M` between prior and new tree to identify renames, then UPDATE `file_changes.rename_from` for the matched pairs. This means renames are recorded but feed display might show as add+delete momentarily until the rename pass completes — acceptable.

## Stage 5 — Annotation delivery

End state: walker can write annotations into `annotations`, the delivery worker routes them per the design's fallback chain, and reset preflight properly flushes pending annotations to talking-stick (filling in stage 1's stub).

### 5.1 Service layer

**File:** `src/watch/annotation-service.ts`

```ts
export interface CreateAnnotationInput {
  changeSeq: number;
  lineSide: "before" | "after";
  lineStart: number | null;
  lineEnd: number | null;
  selectedText: string | null;
  body: string;
  author: string;
}

export class AnnotationService {
  create(input: CreateAnnotationInput): Promise<{ annotationId: string }>;
  retarget(annotationId: string, toAgentId: string): Promise<void>;  // before delivery only
  deliverPending(): Promise<{ delivered: number; failed: number }>;
}
```

`create` writes the row with `delivery_status='pending'`, fsyncs, then asynchronously triggers `deliverPending`.

`deliverPending` walks rows ordered by `created_at`. For each:
1. Reload the change row to find `attributed_to` (via `change_batches` join).
2. Routing chain (design §Annotation delivery):
   - If `attributed_to` is currently active in the room AND (`is_owner` OR `last owner within recent_owner_window_ms`) → `send_message(room_id, to_agent_id=attributed_to, body=formatted)`.
   - Else if `room.owner` is set → `send_message(room_id, to_agent_id=room.owner, body=formatted)`.
   - Else → `add_note(room_id, body=formatted, turn_id=current_turn_or_null)`.
3. Update `delivery_status` and the appropriate id column. Failures keep `pending`.

**DECISION — formatted body.** Implement `formatAnnotation(annotation, change, blob_excerpt)` returning the canonical body shape from design §Annotation format:

```
[diff-walker] <path>:<line_start>-<line_end> (change #<seq>, batch #<batch>)
> <selected_text first 5 lines>
<body>
```

`selected_text` is captured at annotation creation (so blob GC doesn't lose it). Truncate to 1024 chars in the message; full text stays in the local row.

### 5.2 Reset preflight

Replace the stage-1 stub: before reset, call `deliverPending()` to drain the queue. If any rows remain `pending` after delivery attempts and `!force`, throw `PendingAnnotationsBlockReset`. With `--force`, log the lost count and proceed.

### 5.3 Manual retargeting

`retarget(annotationId, toAgentId)` updates pending rows only; rejects with `AlreadyDelivered` for sent/noted rows. Walker UI calls this from the modal's "send to..." menu.

### 5.4 Tests

**File:** `tests/watch-annotations.test.ts`

- create: row with `delivery_status='pending'` exists.
- deliverPending with active attributed agent owning stick → message sent, `delivery_status='sent'`, `message_event_seq` populated.
- deliverPending with attributed-but-stale agent → falls through to current owner.
- deliverPending with no owner → falls through to add_note; `note_id` populated.
- deliverPending with talking-stick send_message failure → row stays pending, `delivery_attempted_at` updated.
- retarget pending row: routes to overridden agent. Retarget already-delivered row: throws.

## Stage 6 — TUI walker

End state: `tt walk` opens a neo-blessed TUI with feed/diff panes, follow/review/hold/compose state machine, line-range selection, annotation modal, manual retargeting, status bar, and the back-step anchor.

### 6.1 Layout

**File:** `src/walk/app.ts`

neo-blessed screen with two child boxes:
- Left feed pane: `Box` + `List` showing visible `file_changes` rows. Width: 40% (configurable via `walker.feed_width_pct`).
- Right diff pane: `ScrollableBox` rendering colored unified diff text.
- Status bar: `Box` at row -1 with mode indicator, room owner, watcher lag, store size.

### 6.2 State machine

**File:** `src/walk/state-machine.ts`

```ts
export type WalkMode = "follow" | "review" | "hold" | "compose";

export interface WalkState {
  mode: WalkMode;
  selectedChangeSeq: number | null;
  backAnchor: number | null;
  composeLayer: "annotation" | "search" | "help" | null;
  newCount: number;
}
```

Transitions per design §Follow/review state machine. When transitioning out of `review`/`compose` to `follow`, capture current selection as `back_anchor`. When `follow` snaps to a new tip, do NOT update `back_anchor` (anchor is for "where I was before live follow," per Codex's clarification).

Idle timer: any recognized key (KeyDown event in blessed) calls `resetIdleTimer()`. Hold-pause key during keydown sets `mode='hold'`; keyup returns to `review` and restarts timer.

### 6.3 Subscriber

**File:** `src/walk/subscriber.ts`

Connects to `watcher.sock`; falls back to polling. Receives `batch_closed` events; queries store DB for new `file_changes` rows where `change_seq > lastSeen`, appends to feed (if `mode='follow'` and settle delay elapsed, advance selection). Also surfaces `pending` annotations as feed indicators.

### 6.4 Diff rendering

**File:** `src/walk/diff-render.ts`

Calls `Projection.diff()` and renders with simple ANSI coloring (red `-`, green `+`, dim hunk headers). For `class='opaque'` or source-truncated changes, render a metadata block instead:

```
~ assets/logo.png
  size: 12,438 → 13,021 bytes
  hash: a3f1ce8d… → b29c4f12…
  binary or unknown file type — hash delta only
```

### 6.5 Annotation modal

**File:** `src/walk/annotation-modal.ts`

Triggered by `enter` on a marked range. neo-blessed `Form` with:
- Read-only target agent (resolved by routing chain at modal-open time)
- Editable target agent override (Tab to expand to picker)
- Multiline body textarea
- `Ctrl+Enter` submit, `Esc` cancel

On submit, calls `AnnotationService.create()`. Walker shows ✎ pending icon next to the change row until delivery completes.

### 6.6 Tests

TUI tests are notoriously brittle. Scope: state machine logic, not screen output.

**File:** `tests/walk-state.test.ts`

- New batch arrives in follow: selection advances to newest after `follow_settle_delay_ms`.

## Risks I'd flag for codex specifically

1. **chokidar fidelity on macOS.** APFS + Spotlight + iCloud can produce duplicate events; we rely on the post-quiet-window scan to dedupe but the test plan should include a stress test.
2. **`git diff -M` performance** on a 10k-source-file projection. Likely fine but unproven; if it becomes a bottleneck, falling back to `--diff-algorithm=histogram` or reducing rename detection scope is the escape valve.
3. **Annotation delivery races** when the operator submits while the watcher is mid-reset. Mitigation: `AnnotationService.create()` takes a lease check; reset blocks on `flushPendingAnnotations()` first.
4. **Subscriber socket lifecycle** during watcher restarts. Walker must handle `ECONNRESET` and reconnect with backoff; subscriber tests should cover that.
5. **TUI tests on CI.** State-machine tests are deterministic and headless-safe; full-screen tests are not. Ship only state-machine tests in CI; manual smoke for layout.
