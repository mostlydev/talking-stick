# Talking Stick 0.31.0

Date: 2026-10-23

## Added

- Releases include a Windows x64 standalone archive (`tt.exe`), contributed by Luke Zekes
  (#173, integrated as #184). `npm run build` and `scripts/build-standalone.mjs` now run on
  Windows, which has no `chmod`. `tt up` finds `tt.exe` and harness executables through
  `PATHEXT`. The Windows binary is built with Bun 1.4.4 so Codex's Windows sandbox sees its
  environment.
- The bottom chat status bar shows when a newer release is available, or when an update is
  already installed and chat needs a restart (#180). Installer-managed copies say
  `tt self-update`; Windows and hand-extracted copies say `download from GitHub`. Startup and
  every chat pane share one cached check of the public `checksums.txt` release asset through
  GitHub's CDN, at most once every 24 hours plus up to 6 hours of jitter, failures included.
  Nothing polls the GitHub API.

## Changed

- Pinned message bodies are replaced by a one-row unread bar at the top of chat: the count,
  the oldest unread sender and a one-line preview (#177). `/unread`, or Ctrl-click on the bar
  in Herdr, visits missed messages oldest-first in their original place in the timeline,
  acknowledging each one only after it is drawn; click again for the next. Escape returns
  live with the draft kept. Inline output stays on normal scrollback until an unread message
  actually scrolls off, and scrolling across an unread message now acknowledges it.

## Fixed

- Operator and urgent messages can steer an active daemon-backed Codex turn instead of
  waiting for it to finish (#178, #181). A message whose delivery is uncertain is recovered
  at most once, only after its exact target turn ends, with its original acknowledgement
  token. Native cancellation reports success only once the turn is seen interrupted.
- The standalone binary releases its database file as soon as it closes, on every platform.
  Bun kept the connection open until prepared statements were collected, and services never
  closed it; Windows exposed this as a locked file.
- Windows `tt up` confirms live agents and chat consoles from process creation times and
  ancestry, with quoted executable paths and `.exe` names (#175). Process snapshots refresh
  outside the room write lock, and a new guardian's identity is read fresh so release can
  stop it. Herdr preflight reports missing session integrations with install commands.
- Windows chat uses the resized pane width immediately after `tt up`.
- Windows sandboxed Claude wakes keep named-pipe connection refusals pending, so the chat
  console can deliver them instead of losing the wake.

## Upgrading and limits

Run `tt self-update`, then restart running `tt chat` consoles and harnesses. After this
release, running chats announce later releases in the status bar themselves.

Windows has no installer yet: download `talking-stick_0.31.0_windows_x64.tar.gz` from the
release, check it against `checksums.txt`, extract it with `tar -xzf`, put the folder on your
`PATH`, and run `tt install --all`. A hand-extracted copy does not update itself. Codex's
restricted Windows sandbox account cannot read process details, so `tt up` launch
confirmation for Codex there remains unconfirmed; see the README.

Hookless Codex sessions recover an uncertain steer only when a later room write happens;
there is no background watchdog. `tt up` still starts agents one at a time (#182), and the
harness picker on first run is tracked in #183.
