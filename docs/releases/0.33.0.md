# Talking Stick 0.33.0

Date: 2026-10-27

## Changed

- Chat's unread view is only about messages addressed to you (#196). Ctrl-G jumps from the
  composer to the oldest unread message for you, keeping the draft, and again for the next;
  typing returns to the composer with those keys in the draft, and Escape still returns live. While
  reviewing, only the message under review is shown at full brightness, however old; the rest is
  gray. The bar ends with `Ctrl-G`, kept even on narrow terminals, and the room strip and `/rooms` count only messages for you across
  your consoles, until acknowledged. Fullscreen's backlog indicator now reads `↓ N more`.

## Added

- `tt supervisor` attempts a Grok worker (`grok agent --no-leader stdio`) in a private `GROK_HOME`.
  It does not prompt, resume, interrupt, or approve. Without credentials in that home, `session/new`
  answers "Authentication required" and the worker is held `crash_loop`, so none starts yet.
  `--env XAI_API_KEY=keychain:SERVICE` names a credential for the child environment only. A missing
  item fails before spawn and the error does not include the secret. That reference is not a proven
  login. A recorded session is held as `resume_failed` rather than replaced. The user's Grok config is never copied.
- `scripts/attended-gate-acceptance.mjs --launchd` is the attended launchd check of the human
  gate's helper. Each step loads a throwaway LaunchAgent, with its own label and its plist in a
  temp root, whose program is a wrapper shell that starts the helper. Steps:
  - confirm and cancel run in `gui/<uid>`
  - in the background `user/<uid>` domain only an observed "unavailable" is accepted; a dialog,
    a load failure or a timeout there fails the run
  - an abort with the dialog up must leave no job or helper
  Nothing counts as unloaded or gone without proof, and a run with cleanup outstanding is never
  accepted. It starts no supervisor and enables nothing. Its `--self-test` uses a stand-in
  launchctl, private to each run, and runs in CI.
- `scripts/attended-gate-acceptance.mjs` is the operator's acceptance of the supervisor's human
  gate. It runs a disposable supervisor whose only worker is a confined fixture, and asks the
  person at the console to confirm and cancel real macOS LocalAuthentication dialogs. It enables
  nothing. Its `--self-test` runs the same steps without a dialog, in CI.
- `tt supervisor` gate eligibility. A human gate may act only while every live worker is
  provably unable to write the supervisor's state, program, launch agent or its own startup
  closure. That is judged from the sandbox the native process reports, never from the spec. An
  ineligible worker is held `gate_ineligible`, and control is refused, rechecked after each answer.
  Claude and Grok workers are always ineligible. The gate still ships locked.
- `tt supervisor` keeps its own state (database, token, sockets, logs, worker homes, process evidence)
  in a protected root outside the tt data directory, which workers must be able to write:
  `~/Library/Application Support/talking-stick/supervisor/<id>` on macOS, or under
  `$XDG_STATE_HOME`. Older state blocks every command until `tt supervisor migrate`, a human-only,
  crash-safe copy that keeps the old files aside.
- `tt supervisor` control now has to pass a human gate that confirms each exact request: the
  approval, its generation and the digest of the detail the human read. The question can't be
  reused or replayed, and a request is checked again after the answer. The gate ships locked. A
  macOS LocalAuthentication helper is the candidate, pending an attended acceptance, and Keychain
  item ACLs were ruled out (Always Allow trusts the calling binary).
- `tt supervisor approvals show <approval-id>` prints the whole native request behind an approval,
  with its SHA-256, so a human never decides on a summary. A request too large to review (over
  128 KiB) is refused and never pending.
- `tt supervisor` control is locked: `approve`, `deny`, `interrupt` and `reconcile` are refused
  until a verified human-control boundary exists, since any same-user process, supervised workers
  included, can read the control token. Pending approvals expire as a deny after 24 hours.
- `tt supervisor` runs Claude workers (`claude -p` stream-json, the stdio permission tool, no user
  settings or MCP servers). It gives each fresh conversation its session id, resumes it after a
  restart, and turns tool prompts into pending approvals, which can't be granted while control is
  locked. A Claude worker's project settings must
  allow `tt` itself, since it can do nothing else without an approval.
- `tt supervisor` (preview): an optional daemon that will start and keep headless harness workers
  running, with per-worker permissions, human-only audited controls and approvals behind a control
  token, and a macOS user agent (`install`/`uninstall`). Room messages reach supervised workers through a fenced, journalled
  delivery, and a restarted worker rejoins with its own credential. The Codex app-server adapter
  supports isolated native sessions on macOS/Linux, idle wake, busy steering, interruption and
  per-request approvals. Enrolment is journalled once per session; credentials are never copied.
  The Codex and Claude adapters are included. A Grok worker is attempted but can't authenticate yet. See `docs/supervisor.md`.
- A Claude or Codex member whose harness reports its session ended is now lost, not removed,
  since an idle conversation can be unloaded while its window stays open. Messages to it are
  kept and reported to senders as held. Its still-running process gets one body-free notice to
  run `tt join`, and only that explicit join recovers it. Recovery has no lease, and the member
  gets back its delivery batches and its place in the room's events. A new session in the same
  single-session process, or the process ending for an hour, ends the loss for good. `tt leave` or
  `tt kick` of a lost member also keeps that session out of the room. Lifecycle hook events are logged for diagnosis, without command lines. `tt msg send` and chat
  mentions reach a lost member, and chat says the message is held.

## Fixed

- Codex queue delivery and its immediate start attempt now use the same configured daemon
  socket, including `CODEX_HOME` and an explicit library socket override. Unloaded threads
  keep their queued envelope; delivery does not resume or adopt an interactive session.
- A member silent for a day was removed on the first reading that found its process gone. The
  hour's grace now runs from that first reading of the same exact process, so a single bad
  reading after a long silence can't remove a member or expire its room. A running reading or
  the member's own `tt` use cancels it.
- A Claude started from another Claude session was anchored to the outer session's process, so
  the outer session's exit or hooks could end the inner one. Claude sessions now anchor to the
  nearest Claude process, including with an inherited `CMUX_CLAUDE_PID`. Codex and Grok anchoring
  is unchanged.

## Verification

Release-candidate checks passed: 1,492 Node tests (1 skipped), 7 Bun SQLite and
service tests, typecheck, build, help, diff and package checks. CI must pass on the
release PR and the merged commit before tagging. The tag workflow builds and
rehearses all five native targets, then publishes their archives with
`checksums.txt`.

The chat changes ran in the operator's own consoles from the shared build before
this release was requested. The supervisor is a preview with control locked: the
gate kit's self-tests run in CI, and its attended foreground and launchd runs are
still pending, so nothing in this release enables approvals. A data directory with
an earlier unreleased supervisor's `supervisor.sqlite` needs `tt supervisor migrate`
before other `tt supervisor` commands run.

npm run typecheck
npm test

npm run test:bun
node dist/cli.js --help
git diff --check
